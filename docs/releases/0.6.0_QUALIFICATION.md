# PyDBAdminKit 0.6.0 — Monitoring / Observability Qualification

## Purpose

This qualification freezes the complete `0.6.x` feature line before stable promotion.

The stable promotion gates are:

```text
health model stable
UNKNOWN semantics stable
threshold configuration stable
machine report stable
```

LOT-17, LOT-18 and LOT-19 are complete.

## Stable health semantics

Aggregation remains:

```text
any CRITICAL  → CRITICAL
else any WARNING → WARNING
else all UNKNOWN (or no checks) → UNKNOWN
else → OK
```

`UNKNOWN` means that health could not be determined. It does not mean healthy.

The stable default CLI policy is:

```text
OK       → exit 0
WARNING  → exit 0
CRITICAL → exit 1
UNKNOWN  → exit 0 by default
```

`--fail-on-warning` promotes WARNING to a non-zero exit. A future
`--fail-on-unknown` policy remains explicitly deferred.

## Stable threshold defaults

| Check | Warning | Critical |
| --- | ---: | ---: |
| Connection utilization | 0.80 | 0.95 |
| Long query | 30 s | 300 s |
| Long transaction | 60 s | 600 s |
| Idle transaction | 60 s | 300 s |
| Waiting locks | 1 | 10 |

Every threshold remains overridable by the `health check` CLI.

## Stable machine report

The health report keeps these top-level fields in order:

```text
overall_status
checks
captured_at
```

Each check exposes:

```text
name
status
message
details
captured_at
evidence
```

Evidence exposes:

```text
metric
observed
warning_threshold
critical_threshold
```

No query text, credential, or secret is part of the health contract.

## Observability foundation

The Core now provides:

- `MetricExporterPort`;
- `MetricDescriptor`;
- `MetricType`;
- default cardinality policy;
- deterministic metric naming;
- `MonitoringSnapshot`;
- `MonitoringSnapshotService`;
- Prometheus and OpenTelemetry design spikes.

Prometheus and OpenTelemetry runtime adapters remain deferred. Their absence does not block
`0.6.0` because the Core exporter boundary is ready.

## Automated qualification

The release-contract test freezes:

- health aggregation precedence;
- mixed OK/UNKNOWN behavior;
- all-UNKNOWN behavior;
- threshold defaults;
- exact machine-health DTO shape;
- public observability boundary.

Existing CI additionally validates:

- Ruff formatting and lint;
- Mypy strict;
- unit coverage >= 85%;
- PostgreSQL integration;
- package build;
- installed-wheel CLI smoke test.

## Promotion decision

All qualification CI gates are green. The `0.6.x` implementation is promoted from
`0.6.0b1` to stable `0.6.0`.

The next roadmap milestone is LOT-20 — Hardening.
